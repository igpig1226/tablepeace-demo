# TablePeace 演示网站

`docs/` 是可部署到 GitHub Pages 的**中文静态交互演示**。它在浏览器内使用明确标注的虚构数据，支持方案对比、规则重组和模拟确认。刷新页面后重置；它不保存真实房间或收集真实成员输入。

根目录的 `server.py`、`app.js` 和 `index.html` 是多人功能原型，已有中文界面。它需要 Python 和 SQLite；GitHub Pages 不运行这部分后端。`render.yaml` 可将它部署为 Render 免费 Web Service。

**一句话介绍：** 一个面向小组决策的共享工作台。每个人私下提交时间、预算和环境要求，系统展示匿名冲突数，帮助组织者调整方案，最后由每个人亲自确认。

## 启动

需要 Python 3.10 或更新版本，无需安装依赖。

在此文件夹执行：

```bash
python3 server.py
```

浏览器打开 <http://127.0.0.1:8000>。也可以在 macOS 双击 `start.command`。

本地 SQLite 数据保存在此文件夹的 `tablepeace.sqlite3`。组织者可在网站的「组织者工具」删除房间及其中的私人数据。

## Render 部署

在 Render 导入此公开仓库并创建免费 Web Service。构建、启动和健康检查配置见 `render.yaml`。服务地址的 `/` 会跳转到中文首页 `/zh/`，`/new` 可建立多人房间。

免费服务将 SQLite 数据放在 `/tmp/tablepeace.sqlite3`。Render 重启或重新部署后，房间及私人输入可能丢失；只适合演示，不适合长期保存真实数据。未设置 AI 环境变量时，AI 笔记提取不可用。

## 5 分钟演示

1. 首页说明问题：四个人各有要求，聊天记录难以汇总。
2. 进入演示，说明示例数据是虚构的。初始三个方案分别有 **3 / 1 / 2** 人被硬性条件挡住。
3. 运行方案重组：把图书馆与 18:00 组合，得到 **0 个已记录冲突**。强调场地仍未核实。
4. 创建多人房间，复制邀请链接。用不同浏览器资料或无痕窗口加入，分别提交条件。
5. 进入「小组方案兼容性」看匿名汇总；在「方案重组」测试、发布新方案。
6. 组织者发起确认。演示 3/4 仍是等待状态，4/4 才显示全员确认。

## 答辩时怎么讲

> TablePeace 把群聊里分散的个人限制转成可检查的方案条件。系统负责找冲突和模拟调整，人负责核实场地并确认承诺。AI 只辅助把个人笔记整理成待审核字段，不能替任何人作决定。

三个关键区别：

- **兼容**：已提交的硬性条件没有冲突。
- **核实**：组织者实际检查过场地，并记录来源。
- **确认**：全部成员对同一版本方案明确选择了 Yes, I can。

## 已实现

- 无账户建房和浏览器会话；3–8 人加入；SQLite 持久化。
- 每人只可读取和修改自己的私人条件。受邀但未加入的人不能读取汇总。
- 确定性规则计算时间、预算和安静环境；未知信息单独显示。
- 方案重组、无写入模拟、组织者发布新方案。
- 每人独立确认；条件修改使旧确认失效；事实准确的摘要复制。
- 房间关闭、场地核实记录、删除；移动端页面。
- 可选 AI 笔记提取接口。只有配置 API 后才可使用；失败时可继续手工填写。

## 可选 AI 配置

使用兼容 OpenAI Chat Completions 的服务时，启动前设置：

```bash
export AI_BASE_URL='https://YOUR_PROVIDER/v1'
export AI_MODEL='YOUR_MODEL'
export AI_API_KEY='YOUR_SECRET'
python3 server.py
```

密钥仅保存在服务端环境变量。没有密钥时，网站会明确提示 AI 不可用。

## 演示边界

这是**演示版**，不是正式产品。合同指定的 Supabase Postgres 和 Next.js 尚未实现；Render 免费服务的 SQLite 数据也不持久。公开交付前需迁移到云数据库，并完成隐私和并发测试。不要把示例数据说成真实调研结果。
